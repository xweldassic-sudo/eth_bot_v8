# Бот сигналов ETH по системе Crypto Rait

Бот следит за ETH-USDT (бессрочный фьючерс BingX) и присылает в Telegram картинку графика с зонами, входом, стопом и тейком и текст с причиной. Сделки бот не открывает.

- **1H**: только развороты от ваших зон. Поддержка: только покупки, сопротивление: только продажи.
- **15m**: только по тренду (HH+HL или LH+LL по swing-точкам, N=3 (`SWING_N_15M`); если такого нет, то бычий тренд: более высокий минимум и закрытие выше последнего максимума, медвежий: более низкий максимум и закрытие ниже последнего минимума), вход на откате по паттерну. Если начинается разворот против позиции, бот присылает сигнал закрыть. Тренд проверяется и «вживую»: swing-точкам нужны 3 свечи справа, поэтому, если откат уже ушёл ниже начала последней волны (низ паузы между двумя микро-вершинами; новый минимум ниже прежнего), тренд считается сломанным и входов против нового движения нет, не дожидаясь подтверждения swing-точек.
- Паттерны: пин-бар, поглощение, внутренний бар, PPR, Fakey, с иерархией и отменами из правил. Поглощение засчитывается, только если тело поглощающей свечи не меньше 30% её диапазона (иначе цвет свечи зависит от биржи) и у неё нет длинного шипа против направления (это уже пин-бар в другую сторону).

## Установка (Windows, macOS, Linux)

1. Установите Python 3.11 или новее (на Windows отметьте «Add Python to PATH»).
2. Распакуйте архив, откройте терминал в папке `eth_bot` и выполните:
   ```
   python -m venv .venv
   .venv\Scripts\activate        (Windows)
   source .venv/bin/activate     (macOS/Linux)
   pip install -r requirements.txt
   ```
3. В Telegram откройте @BotFather, отправьте `/newbot`, получите токен.
4. Скопируйте `.env.example` в `.env` и впишите токен в `TELEGRAM_TOKEN`. Токен никому не пересылайте.
5. Запустите `python bot.py` (он запускает бота под супервизором, см. раздел «Устойчивость связи»), напишите своему боту `/start`. Он ответит ID чата. Пока `CHAT_ID` не задан, бот работает в режиме настройки: отвечает только на `/start` и `/id`, команд и сигналов нет, чужие люди ничего изменить не могут.
6. Впишите этот ID в `CHAT_ID` в `.env`, остановите бота (Ctrl+C) и запустите снова. Теперь бот отвечает только вам.

Бот работает, пока открыт терминал и включён компьютер. Если бот был выключен, при запуске он догоняет пропущенные свечи: обновляет зоны, ордера и сделки (стоп, тейк, срабатывание ордера, срок жизни), но новых сигналов по старым свечам не присылает. Старые команды, накопившиеся за время простоя, не выполняются.

## Команды

| Команда | Что делает |
|---|---|
| `/zone R 2300 2320` | добавить зону сопротивления (границы в любом порядке, можно с запятой) |
| `/zone S 2100 2120` | добавить зону поддержки |
| `/zones` | список зон с номерами |
| `/del 3` | удалить зону #3 |
| `/chart` или `/chart 15m` | свежий график с зонами |
| `/status` | настройки, число зон, ожидающих ордеров, очередь |
| `/addtrade L 2400 2380 2440 1h` | записать сделку, открытую вручную (L лонг, S шорт; последний параметр 1h или 15m, по умолчанию 1h) |
| `/trades` | открытые сделки и ожидающие ордера с номерами |
| `/addresult L 2400 2380 2440 tp 19.11 14:30` | записать уже закрытую сделку в итоги с датой (МСК). Результат stop, tp или exit; для exit добавьте цену закрытия: `exit 2415 19.11 14:30 15m` |
| `/results` | итог по всем закрытым сделкам (стоп, тейк, закрытие по сигналу): число, сумма в R и $, нарастающий итог и график |
| `/deltrade 3` | убрать сделку или ордер #3 из отслеживания (после ручного закрытия) |

Зона удаляется сама, когда свеча 1H закрылась за её дальней границей (у сопротивления выше верхней, у поддержки ниже нижней). Об этом приходит уведомление.

## Какие уведомления приходят

- Сигнал на вход: направление, паттерн и его описание, зона, вход и тип ордера, стоп, тейк, R:R, объём при риске 10$, примерная сила давления на зону в %.
- Пропуск входа на 1H: паттерн у зоны есть, но R:R до противоположной зоны меньше 1:2, или конфликт паттернов.
- Отмена входа: отложенный ордер не сработал, а свеча закрылась за стопом, либо истёк срок жизни ордера: 3 свечи его таймфрейма после сигнальной (`PENDING_TTL_CANDLES`). Ордер может сработать и на третьей свече.
- PPR: первое сообщение при формировании, второе, если следующая свеча закрепилась за 50% свечи PPR или вернулась к точке входа.
- 15m: сигнал закрыть позицию при развороте или сломе структуры.
- Срабатывание отложенного ордера (ОРДЕР СРАБОТАЛ). Если на той же свече был достигнут стоп, придёт и сигнал стопа (порядок внутри свечи неизвестен, поэтому стоп считается всегда; тейк на свече входа считается только для стоп-ордеров, не для лимитных).
- Фейк (Fakey) на 1H: уведомление в любую сторону, даже если свеча далеко от зоны, вход по фейку не открывается. Фейк на продажу отменяет ещё не сработавший ордер внутреннего бара на покупку, фейк на покупку отменяет ордер на продажу. Внутренний бар не считается сигналом, если фейк против его направления был на этой или предыдущей свече. Открытая сделка по внутреннему бару закрывается, если потом сформировался фейк против неё. Остальные паттерны на 1H только в сторону зоны. На 15m фейк и внутренний бар не блокируются.
- Стоп-лосс, тейк-профит и закрытие сделки (по смене тренда на 15m и по слому структуры). Касания стопа, тейка и входа бот ловит по закрытым 15m-свечам для сделок обоих таймфреймов, то есть уведомление приходит не позже чем через 15 минут (а не при закрытии часа). Смена тренда, слом структуры и PPR по-прежнему проверяются по закрытию свечи своего таймфрейма.
- Одна сделка в одну сторону на каждый таймфрейм: пока открыта сделка или ожидает ордер на покупку на 1H, новая покупка на 1H не открывается (то же для продаж и для 15m). Сделки 1H и 15m в одну сторону могут быть открыты одновременно. Пропуск на 1H сообщается, на 15m нет.
- Удаление зоны.

Уведомления приходят круглосуточно: ночных тихих часов больше нет, сигналы на вход, сделки и ордера отслеживаются 24/7. Напоминание в 21:30 убрано, оно было нужно только из-за тихих часов.

## Настройки (config.py)

| Параметр | Значение | Откуда |
|---|---|---|
| `RISK_USD`, `RR` | 10$, 1:2 | ваше решение |
| `STOP_BUFFER_1H` | 0,1% | ваше решение (0,05-0,1%) |
| `STOP_BUFFER_15M` | 0,5% | ваше решение (0,5-1%) |
| `SWING_N` | 5 | ваше решение |
| `CONFIRM_REVERSAL_1H` | False | ответы расходятся, ждёт вашего решения |
| `ENGULF_MIN_BODY` | 0,3 | по вашему замечанию: минимальное тело поглощающей свечи (доля диапазона) |
| `LEG_DIP_MULT`, `LEG_LOOKBACK` | 2, 30 | по вашему замечанию: насколько глубокой должна быть пауза, чтобы её низ считался началом волны (в медианных свечах за 30 свечей); больше значение, тем реже тренд считается сломанным |
| `PULLBACK_MIN` | 0,382 | моё допущение: минимальная глубина отката на 15m |
| `ENTRY_MAX_RETRACE` | 0,5 | моё допущение: не входить в середине движения (видео про мусорный график) |
| `PRESSURE_BARS` | 5 | моё допущение: свечи подхода для оценки давления |
| `PENDING_TTL_CANDLES` | 3 | ваше решение: срок жизни отложенного ордера в свечах |
| `POLL_STALL_SEC` | 300 | сторож: сколько секунд `getUpdates` может молчать до перезапуска |
| `TG_*_TIMEOUT` | 10–30 с | таймауты Telegram через прокси |

Допущения проверим и подберём на бэктесте.

## Журнал результатов

Каждое закрытие (стоп, тейк, закрытие по сигналу или фейку) дописывается в `data/results.jsonl` до сохранения состояния. Повторная запись одного и того же закрытия после перезапуска не дублирует результат. `/results` читает этот файл, поэтому итог не теряется при перезапуске или выключении компьютера. В R стоп равен -1, тейк равен реальному R:R сделки (у зоны-цели он может быть больше +2, как в сообщении о входе), закрытие по сигналу считается по цене закрытия. В долларах: R умножается на риск 10$.

## Логи

Если Telegram не принял сообщение, бот повторяет отправку (паузы 2, 5 и 15 с), а затем сохраняет уведомление в очередь `data/state.json` и досылает при следующих проверках. Запись удаляется только после успешной отправки.

Все события пишутся в `logs/bot.log` (и в терминал). Файл ротируется по 5 МБ, хранится 5 файлов.
- `бот запущен, PID ...` при каждом старте.
- `новая закрытая свеча` для каждого таймфрейма и число найденных событий.
- `бот работает, проверок с запуска: N` раз в 30 минут: если этой строки долго нет, процесс остановился.
- Повторные попытки BingX (`code 100410`) с номером попытки и паузой.
- `ERROR` с трейсбеком при ошибке цикла или отправки уведомления.
- `CRITICAL` при необработанном исключении, после которого процесс завершается.
- `бот остановлен`, если polling завершился штатно.

Чтобы понять остановку, пришлите `logs/bot.log` за нужный период.

## Устойчивость связи с Telegram

Бот получает команды через длинный запрос `getUpdates`, а уведомления шлёт отдельными запросами. Через нестабильный прокси первый канал может отвалиться, пока второй работает: тогда уведомления идут, а команды нет. Что сделано:

- **Лог команд.** Каждая входящая команда пишется в `logs/bot.log`: `команда получена: /status | чат 123 | принята`. Если команды в логе нет, она не дошла до бота. Если написано «отклонена: чужой чат», команду отправили не из чата `CHAT_ID`.
- **Короткие сетевые ошибки.** Обрыв связи пишется одной строкой с числом ошибок подряд, а не трейсбеком на 100 строк. Восстановление связи тоже пишется в лог.
- **Таймауты и пулы.** Увеличены таймауты соединения и загрузки картинок (раньше 5 с, и `/chart` падал по таймауту), обычные запросы и `getUpdates` идут через разные пулы соединений. Команды обрабатываются параллельно, медленная команда не блокирует остальные. Прокси можно задать явно: `TELEGRAM_PROXY=http://host:port` в `.env`. Без него используется системный.
- **Сторож.** Бот запоминает каждый успешный `getUpdates`. Если ответов нет `POLL_STALL_SEC` секунд (5 минут), сторож (отдельный поток, работает даже при зависшем цикле) завершает процесс, а супервизор поднимает бота заново за несколько секунд. После перезапуска бот пишет в чат, что команды не принимались и их надо повторить. Состояние на диске, а пропущенные свечи бот догоняет сам.
- **Супервизор** (`supervisor.py`). `python bot.py` запускает бота дочерним процессом (`bot.py --worker`) и перезапускает его после сбоев и после сторожа. Он не перезапускает при Ctrl+C, при ошибке настройки (`.env`) и если бот 3 раза подряд падает сразу после старта (причина в `logs/bot.log`). Если бота запускает systemd, Docker или планировщик, запускайте `python bot.py --worker` и включите автоперезапуск: сторож завершает процесс с кодом 75.
- **Реже запросы к BingX.** Свечи запрашиваются только после ожидаемого закрытия свечи (раньше каждые 30 с, из-за чего биржа отвечала лимитом `code 100410`). Если биржа ещё не отдала новую свечу, запрос повторяется на следующем тике.

## Размещение на хостинге

- Запускайте только один экземпляр с одним токеном (иначе Telegram вернёт `Conflict`). Локальный бот перед переездом остановите.
- Токен и `CHAT_ID` можно передавать переменными окружения хостинга, файл `.env` не обязателен.
- Папка `data/` (зоны, состояние, журнал результатов) должна лежать на постоянном диске. На платформах с временным диском она пропадает при каждом рестарте.
- Папку `data/` при переезде скопируйте на новое место.

## Проверка

`pip install -r requirements-dev.txt`, затем `python -m pytest -q tests`. Тесты покрывают паттерны, удаление зон, фильтр R:R, PPR, срок жизни ордеров, касания по 15m, доставку и очередь, `CHAT_ID`.
